# WoW64 Wine on Ubuntu 26.04 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Remove every 32-bit Linux package from docker-wine by switching to Wine's WoW64 mode, which requires moving docker-remote-desktop and docker-wine from Ubuntu 24.04 (noble) to Ubuntu 26.04 (resolute).

**Architecture:** WineHQ publishes WoW64 builds only for resolute: a single amd64 `wine-stable` package containing 32-bit Windows DLLs (`lib/wine/i386-windows/`) and no 32-bit Linux code. docker-remote-desktop moves its base to `ubuntu:26.04`, which brings xrdp 0.10 and needs a socket-path fix. It publishes a new `resolute` tag. docker-wine then rebuilds on that tag from the resolute WineHQ suite, without `dpkg --add-architecture i386`.

**Tech Stack:** Docker/BuildKit, Ubuntu 26.04 apt (snapshot-pinned), WineHQ 11.0 stable, xrdp 0.10.1/xorgxrdp 0.10.2, bash test suites (`tests/run IMAGE`), GitHub Actions, Renovate.

**Spec:** There is no separate spec document. The requirement is the user's request of 2026-10-12: "Update docker-remote-desktop and docker-wine to remove 32-bit Linux packages, switch to Wine's new WoW64 mode." The facts below were checked on 2026-10-12, in spike builds of both images on `ubuntu:26.04` that passed both full test suites.

## Background (verified facts the tasks rely on)

- `https://dl.winehq.org/wine-builds/ubuntu/dists/noble/` only offers the classic multiarch build: `wine-stable` depends on `wine-stable-i386`. `dists/resolute/` has `binary-amd64` only (no `binary-i386`). There, `wine-stable 11.0.0.0~resolute-1` is self-contained: 1071 files in `lib/wine/i386-windows/`, none in `i386-unix/`, and no `wine64` binary.
- Why this matters: Docker 29.4.2 (the `ubuntu-26.04` GitHub runner) blocks `socketcall(2)` in its seccomp profile, which breaks every 32-bit glibc program (`wine: socket : Function not implemented`), see actions/runner-images#14790. A WoW64 image has no 32-bit Linux processes, so it is immune.
- Ubuntu 26.04 has every package both images install, except `p7zip`. Use `7zip` instead (it `Provides: p7zip, p7zip-full` and installs `/usr/bin/7z` and `/usr/bin/7za`).
- Ubuntu 26.04 ships xrdp `0.10.1` (noble: `0.9.24`). Two changes affect this sesman-less setup:
  1. xrdp-chansrv 0.10 always listens on `<socket root>/<uid>/xrdp_chansrv_socket_<display>`. There is no environment override. Ubuntu compiles the socket root as `/run/xrdp/sockdir`, so the directory is `/run/xrdp/sockdir/$(id -u)`. Xorg (xorgxrdp) and the PulseAudio module still honour `XRDP_SOCKET_PATH`.
  2. Without sesman, xrdp resolves `chansrvport=DISPLAY(10)` with uid `-1` (that is, `/run/xrdp/sockdir/-1/...`). Both `chansrvport` and libxup's `port` accept an absolute socket path, so write explicit paths into `xrdp.ini`.
  3. The xrdp log line for a session changed from `connected to X11rdp_pid=` to `connected to Xorg_pid=`.
- apt 3.2 on 26.04 still honours `Snapshot:`. `apt-cache policy` lists only `snapshot.ubuntu.com/ubuntu/<id>` sources (it also downloads the live `InRelease` files, but they are not used as package sources).
- A seed-mode prefix created by the current noble image (`ghcr.io/kamphaus/docker-wine:stable`) works unchanged under the WoW64 image. Registry contents are kept, and both `wine cmd` and `wine C:\windows\syswow64\cmd.exe` run.
- Under WoW64, `WINEARCH=win32` fails with `wine: WINEARCH is set to 'win32' but this is not supported in wow64 mode.`, and `wine64` no longer exists (only `wine`).

```bash
#!/usr/bin/env bash
# The image runs Wine in WoW64 mode: no 32-bit Linux packages, yet 32-bit Windows programs run.
source "$(dirname "$0")/../lib.sh"

out=$("$RUNTIME" run --rm --entrypoint bash "$IMAGE" -c \
    'dpkg --print-foreign-architectures; dpkg-query -W -f "\${Package}:\${Architecture}\n" | grep -v ":amd64$\|:all$" || true') \
    || fail "could not list installed packages"
[ -z "$out" ] || fail "non-amd64 architectures or packages present: $out"

out=$("$RUNTIME" run --rm --entrypoint bash "$IMAGE" -c 'command -v wine64 || true')
[ -z "$out" ] || fail "wine64 present ($out): not a WoW64 build"

# Runs as uid 123456 (run_cmd): 32-bit programs must work without libnss-wrapper:i386
out=$(run_cmd "$IMAGE" bash -c 'xvfb-run -a wine "C:\\windows\\syswow64\\cmd.exe" /c ver 2>/dev/null') \
    || fail "32-bit cmd.exe failed: $out"
grep -q "Microsoft Windows" <<<"$out" || fail "32-bit cmd.exe printed: $out"
pass
```

This makes it work on hosts that cannot run 32-bit Linux programs, such as kernels without IA32 emulation or Docker 29.4.2, whose seccomp profile blocks `socketcall(2)`. When moving a derived image from the earlier Ubuntu 24.04 based image:

```markdown
- Call `wine`, not `wine64`; there is no `wine64` binary.
- Remove `WINEARCH=win32`. WoW64 only supports 64-bit prefixes (`wine: WINEARCH is set to 'win32' but this is not supported in wow64 mode.`), and 32-bit programs run in them.
- Do not install `:i386` packages; there is no i386 architecture or WineHQ i386 repository for Ubuntu 26.04.
- Existing prefixes in user volumes keep working; no reseed is needed for the switch itself.
```
